# PHP-админка «Спектра»

Локальная админка для созданной базы `spektr_okna`. PHP 8.1+ с `pdo_mysql`
и `session`, MySQL 8.0+. Composer и сборка JavaScript не требуются.

## Запуск на Mac

Из папки `/Users/user/Desktop/окна сайтик` (в которой лежит `spectr-okna`):

```sh
brew install php
brew services start mysql
python3 spectr-okna/tools/start-admin.py
```

Если терминал уже открыт в `spectr-okna`, команда запуска:

```sh
python3 tools/start-admin.py
```

Открыть **http://127.0.0.1:8002/admin/**. Логин `admin`, пароль — тот,
который был задан при `setup-database.py`. Запускать импорт заново не нужно.
Для остановки нажать Ctrl+C в терминале. Другой порт: `--port 8003`.
Сам сайт доступен по адресу http://127.0.0.1:8002/.

Если база ещё не создана:

```sh
python3 spectr-okna/tools/setup-database.py
```

Обычный Node preview не исполняет PHP и намеренно не открывает `/admin/`.
Для админки используйте новый PHP-запускатель; он также поддерживает
частичные запросы MP4, необходимые для видео при прокрутке.
Счётчики статей в PHP preview пока не подключены: на сайте отображается «—».

## Как пользоваться

1. Выберите раздел в верхних вкладках.
2. Выберите страницу слева или нажмите «Добавить страницу».
3. На вкладке «Основное» измените название, адрес, состояние и текстовые блоки.
4. На вкладке «Записи» добавляйте, редактируйте и удаляйте товары, отзывы,
   филиалы, фото и разделы статей. В каталоге есть дополнительные переключатели
   категорий, подборок и цен. Списки и вложенные пункты редактируются полями,
   без ручного ввода JSON. Для изображений указывается путь к существующему файлу;
   загрузка новых файлов пока не реализована.
5. Во вкладке «SEO» задайте поисковый заголовок, описание и canonical.
6. Нажмите «Сохранить изменения». Изменения отдельных записей до этого момента
   находятся только в форме. При переходе на другую страницу редактор предупредит
   о несохранённых правках.

Удаление отдельной записи подтверждается в диалоге и сохраняется вместе со
страницей. «Удалить страницу» после подтверждения сразу удаляет строку
и всё её содержимое из MySQL. Для главной допускается только адрес `/`.
Дочерние страницы должны оставаться внутри выбранного раздела.
Изменения из устаревшей вкладки отклоняются с сообщением о конфликте;
можно скопировать свои правки перед загрузкой свежей версии.

Текстовые поля обычных страниц меняют сохранённый снимок `main_html`.
При необходимости HTML доступен в отдельном сворачиваемом блоке.
Структурированные записи и снимок HTML хранятся независимо: будущая публикация
должна выводить коллекции и статьи из структурированных данных.

**Сейчас админка управляет записями базы. Изменения ещё не публикуются
в статические HTML/JS-файлы сайта.** Переключатель «Страница включена» сохраняет
`is_published` в MySQL и пока не скрывает соответствующий HTML-файл на сайте.
Удаление строки из базы также не удаляет исходный HTML-файл. Подключение вывода
сайта к БД или генерации при публикации — отдельный этап.

## Подключение к базе

По умолчанию: `127.0.0.1:3306`, база `spektr_okna`, пользователь `root`,
пустой пароль. Это настройки для локальной базы из предыдущего шага.
Для других настроек, находясь в `spectr-okna`:

```sh
mkdir -p .data
cp admin/config.example.php .data/admin-config.php
```

Измените значения в `.data/admin-config.php`. Папка исключена из Git.
Также поддерживаются переменные окружения `SPEKTR_DB_HOST`, `SPEKTR_DB_PORT`,
`SPEKTR_DB_NAME`, `SPEKTR_DB_USER`, `SPEKTR_DB_PASSWORD`, `SPEKTR_DB_SOCKET`.
Окружение имеет приоритет над локальным файлом. На хостинге используйте
отдельного пользователя MySQL с правами только на базу сайта.

Вход использует существующий bcrypt-хеш из `admins`; отключённые администраторы
не могут войти. Авторизация проверяется при каждом запросе. Сеанс истекает
после двух часов бездействия. Есть CSRF-проверка всех изменений, ограничение
попыток входа, подготовленные SQL-запросы и защита от потери параллельных правок.

## Размещение в ISPmanager

После возвращения доступа к панели выберите установленную поддерживаемую
версию PHP 8.x с `pdo_mysql`, настройте HTTPS и подключение к MySQL.
Режим `php -S` используется только локально; на хостинге нужен обработчик PHP.
PHP-процессу нужны права записи в `.data` для ограничения попыток входа.

Приложение размещается в корне домена; админка — `/admin/`.
На Apache включите `mod_rewrite` и использование корневого `.htaccess`.
Если статику обслуживает Nginx, запреты нужно добавить в конфигурацию Nginx
перед общим PHP location: `.htaccess` на него не действует.

```nginx
location ~ (^|/)\. { return 404; }
location ~ ^/(database|tools|tests|docs|content|templates|node_modules)(/|$) { return 404; }
location ~ ^/admin/(lib(/|$)|config\.example\.php$) { return 404; }
```

Перед размещением проверьте ответы 404 для `/.data/admin-config.php`,
`/database/init.sql` и `/admin/lib/app.php`. Удобнее вообще не загружать
`tools`, `tests`, `docs` и `database` в публичную папку хостинга.
Настройки конкретного сервера ещё не проверены: доступа к панели пока нет.

## Проверки

```sh
node --test tests/admin.test.js tests/database.test.js
python3 tests/admin-integration.py
```

HTTP-тест требует работающие PHP и MySQL. Он создаёт случайную временную базу,
импортирует схему, проверяет вход, CSRF, добавление/изменение/удаление,
конфликты, запрет исходных файлов и выход, затем удаляет только свою тестовую БД.
Рабочая `spektr_okna` в тесте не используется. Пользователю MySQL для теста
нужны права создания и удаления временной базы; логин можно задать `--user`.
