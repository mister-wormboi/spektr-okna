# Локальная база «Спектра»

Требуется MySQL 8.0+ и Python 3. На Mac MySQL уже установлен через Homebrew.
Файлы в этой папке создают структуру и начальное содержимое.
[PHP-админка](../admin/README.md) уже позволяет редактировать записи в MySQL.
Публичные страницы пока продолжают работать с HTML, JSON и JavaScript-файлами.

## Запуск

Из папки `spectr-okna`:

```sh
brew services start mysql
python3 tools/setup-database.py
```

Скрипт проверит подключение, запросит пароль MySQL (Enter, если его нет),
затем дважды попросит новый пароль администратора. Создаст базу `spektr_okna`,
13 таблиц и наполнит их содержимым текущего сайта. Логин администратора — `admin`.

Пароль администратора: 12–72 байта UTF-8, для латинских символов это 12–72 знака.
Для хеширования используется bcrypt с cost 12 через PHP CLI или системный
`htpasswd`. На этом Mac доступен `/usr/sbin/htpasswd`; устанавливать PHP только
для создания базы не требуется. Полученный хеш совместим с PHP `password_verify`.
Пароли вводятся скрыто, не передаются аргументами процессов и не записываются
в SQL-файл. Пароль MySQL временно хранится в файле с правами 0600, удаляемом
по завершении работы. Пользователь админки и пользователь MySQL — разные сущности.

Другой пользователь/название базы:

```sh
python3 tools/setup-database.py --database spektr_dev --user root --admin-login owner
```

На хостинге сначала создайте базу и пользователя в ISPmanager. Затем запустите
скрипт на сервере, где установлен Python и клиент MySQL:

```sh
python3 tools/setup-database.py --existing-database --database ИМЯ_БАЗЫ --user ПОЛЬЗОВАТЕЛЬ_БАЗЫ
```

Доступны также `--host`, `--port`, `--socket` и `--no-admin`. Не открывайте
удалённый доступ к базе только ради импорта: можно импортировать `init.sql`
через инструменты хостинга.

## Что внутри

Одна таблица на раздел сайта. У таблиц страниц одинаковые поля: `id`, `path`,
`title`, `content` (JSON), `seo_title`, `seo_description`, `canonical_url`,
`is_published`, `created_at`, `updated_at`. Уникальный `path` задаёт адрес страницы.

| Таблица | Начальное содержимое |
| --- | --- |
| `page_home` | Главная, общие шапка и подвал, название сайта и телефон |
| `page_about` | О компании |
| `page_articles` | Список, 10 статей и переходы со старых адресов; статья — отдельная строка |
| `page_calculator` | Страница калькулятора; формула пока остаётся в `calculator.js` |
| `page_catalog` | Каталог и страница окон; 41 товар, категории, подборки, ориентиры цен |
| `page_contacts` | Общая страница с 6 филиалами и 5 страниц городов |
| `page_information` | Вопросы и ответы |
| `page_request` | Переход на блок заявки главной страницы |
| `page_reviews` | Отзывы с авторами, датами и данными источника |
| `page_solutions` | Примеры работ и 35 фотографий с описаниями |
| `page_ustanovka_okon` | Страница установки окон |
| `page_window_inside` | Страница устройства окна |
| `admins` | Администраторы: `id`, `login`, `password_hash`, `is_active`, даты |

Всего 38 строк страниц. Списки товаров, филиалов, фотографий и отзывов лежат
в JSON соответствующей страницы, без дополнительных таблиц и связей.
Статьи хранят полный исходный объект `content.article`: разделы, автор,
обложка, даты и связанные материалы. Список статей содержит только их адреса.

`content.main_html` — снимок текущего `<main>` для переноса текстов и оформления,
а не готовый механизм публикации. Рядом с ним лежат структурированные данные
там, где они уже есть в проекте. Будущий обработчик должен использовать
структурированные данные для вывода коллекций и статей; редактирование
`content.article` само по себе не перепишет снимок HTML или файлы сайта.
Ссылки внутри снимков HTML остаются относительными к исходному адресу страницы.
Для обычных страниц сохраняется HTML; админка предоставляет текстовые поля
для его блоков и расширенный режим разметки. CSS, JavaScript, изображения
и видео остаются файлами.

Общие данные находятся в записи `page_home` с `path = '/'`:
`content.site`, `content.header_html`, `content.footer_html`.
В главной указаны ссылки `content.collections` на страницы с общими коллекциями.
Старые адреса содержат `content.redirect_to`, включая якорь заявки.
Просмотры статей начинаются с нуля. Локальный `.data/article-views.json`
не импортируется; работающий счётчик ещё не подключён к MySQL.

## Повторный импорт и обновление исходных данных

Повторный запуск добавляет только отсутствующие страницы. Существующие тексты,
состояние публикации и пароли администраторов не изменяются. Удаления и сброса
базы в скрипте нет. Если нужный администратор существует, его пароль не запрашивается.
Для добавления другого администратора укажите новый `--admin-login`.

Чтобы пересобрать SQL после изменения файлов сайта:

```sh
node tools/build-database.js
```

Генератор использует актуальный `assets/js/products-data.js`, исходные JSON
в `content/` и все `index.html`. Вручную редактировать `init.sql` не нужно.
Повторный импорт пересобранного файла не обновляет существующие строки;
это начальное наполнение, а не синхронизация сайта и базы.

Импорт только структуры и страниц в уже созданную базу:

```sh
mysql --default-character-set=utf8mb4 -u root -p spektr_okna < database/init.sql
```

При таком импорте `admins` будет пустой: пароль по умолчанию не предусмотрен.
Для создания администратора запустите `setup-database.py`.
DDL выполняется до транзакции; при ошибке создания таблиц уже созданные таблицы
останутся. Наполнение страниц выполняется в транзакции, администратор добавляется
после её успешного завершения. Скрипт не изменяет существующую схему таблиц.

Проверка после импорта:

```sql
SELECT path, title FROM page_articles ORDER BY id;
SELECT JSON_LENGTH(content, '$.catalog.products') AS products
FROM page_catalog WHERE path = '/catalog/';
SELECT id, login, is_active FROM admins;
```

Ожидается 41 товар. Админку подключаем через PHP, проверяя bcrypt-хеш функцией
`password_verify`; сам браузер к MySQL не подключается.
